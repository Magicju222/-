# 第一阶段：需求分析与架构设计

## 1. 项目背景与目标
本项目 "AI Excel Cleaner" 目前是一个基于 Streamlit 的数据清洗工具，集成了 Supabase 身份验证。
为了提升系统的可维护性、安全性和运营能力，需要开发一个独立的**后台管理系统**。
该系统将允许管理员管理用户、监控系统状态、配置全局参数以及查看数据处理日志。

## 2. 功能需求梳理

### 2.1 现有功能模块分析
*   **用户认证模块**: 目前仅有基本的注册/登录/注销功能。用户信息存储在 Supabase Auth 中。
*   **数据清洗模块**: 核心业务逻辑，包含文件上传、表头处理、数据清洗、文件下载。
*   **UI 交互模块**: Streamlit 界面，包含多语言支持。

### 2.2 后台管理新增需求
根据项目规划，后台管理系统需包含以下核心模块：

#### A. 用户管理 (User Management)
*   **用户列表**: 展示所有注册用户（ID、邮箱、注册时间、最后登录时间）。
*   **用户状态管理**: 封禁/解封用户，重置密码（发送邮件）。
*   **角色管理 (RBAC)**: 分配用户角色（普通用户、管理员、超级管理员）。

#### B. 内容与数据管理 (Content & Data Management)
*   **清洗日志**: 记录每次清洗任务的元数据（用户ID、文件名、文件大小、处理行数、耗时、状态）。
*   **文件留存 (可选)**: 如果开启文件存储，需管理上传的历史文件（下载/删除）。

#### C. 系统配置 (System Configuration)
*   **全局参数**:
    *   允许上传的最大文件大小 (MB)。
    *   允许的文件后缀 (xlsx, csv)。
    *   默认清洗规则配置。
*   **公告管理**: 发布系统公告，在前端显示。

#### D. 数据统计与监控 (Dashboard)
*   **核心指标**: 总用户数、今日新增用户、今日清洗次数、累计处理数据行数。
*   **图表展示**: 用户增长趋势图、清洗任务活跃度热力图。

#### E. 安全与审计 (Security & Audit)
*   **操作日志**: 记录管理员的所有敏感操作（如封禁用户、修改配置）。

## 3. 架构设计

### 3.1 总体架构
采用 **前后端分离** 架构，确保管理端的高性能和灵活性。

*   **前端 (Frontend)**: 单页应用 (SPA)，负责页面展示和交互。
*   **后端 (Backend)**: RESTful API 服务，处理业务逻辑和数据访问。
*   **数据库 (Database)**: 利用现有的 Supabase (PostgreSQL) 存储业务数据。

### 3.2 响应式设计
管理后台将采用响应式布局，自动适配：
*   **PC 端**: 完整的三栏/两栏布局，展示详细数据表格。
*   **移动端**: 折叠侧边栏，卡片式展示核心数据，便于随时随地管理。

## 4. 技术栈选型

### 4.1 前端 (Frontend)
*   **框架**: **React** (v18+)
*   **构建工具**: **Vite** (高性能构建)
*   **UI 组件库**: **Ant Design Pro** (企业级中后台最佳实践，内置丰富的图表和布局)
*   **状态管理**: Zustand 或 React Query
*   **HTTP 客户端**: Axios

### 4.2 后端 (Backend)
*   **框架**: **FastAPI** (Python)
    *   *理由*: 项目核心逻辑 (`cleaner.py`) 是 Python 编写的，使用 FastAPI 可以直接复用现有代码，且性能优异，自动生成 OpenAPI 文档。
*   **运行时**: Python 3.9+

### 4.3 数据库与认证 (DB & Auth)
*   **数据库**: **Supabase (PostgreSQL)**
    *   复用现有数据库，无需迁移。
*   **认证**: **Supabase Auth**
    *   支持 JWT Token，与前端和后端完美集成。
